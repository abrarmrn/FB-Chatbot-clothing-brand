# Google Sheets schema

Create one Google Spreadsheet (e.g. `FB-Chatbot-DB`) with **three tabs** below.
The sheet ID goes into n8n credentials and into the workflow's `Sheet ID` env.

The first row of every tab MUST be the header row (exact column names, case-sensitive).
n8n's Google Sheets node uses the header row to map fields.

---

## Tab 1: `Users`

One row per Messenger user (PSID = Page-Scoped ID).

| Column            | Type     | Notes                                                                 |
| ----------------- | -------- | --------------------------------------------------------------------- |
| `psid`            | string   | Primary key. Facebook sender.id. Lookup column.                       |
| `name`            | string   | First + last name from FB profile (filled on first contact).          |
| `ai_enabled`      | boolean  | `TRUE` / `FALSE`. **Gate column** — if `FALSE`, AI never replies.     |
| `status`          | string   | `new` \| `lead` \| `customer` \| `closed`                             |
| `last_user_msg`   | string   | Last incoming text (or transcription).                                |
| `last_bot_msg`    | string   | Last AI reply sent.                                                   |
| `last_message_at` | ISO date | Updated on every inbound. Used by lead-followup scheduler.            |
| `memory`          | string   | JSON-encoded array of last 5 turns: `[{"role":"user","content":"..."}]`. |
| `followup_count`  | number   | How many follow-ups we have already sent (cap at 2).                  |
| `created_at`      | ISO date | First contact.                                                        |

> Tip: format `ai_enabled` column as a checkbox in Google Sheets so a human can flip
> it back to TRUE after handling a ticket.

---

## Tab 2: `Orders`

One row per order. Multiple orders per PSID allowed.

| Column          | Type     | Notes                                              |
| --------------- | -------- | -------------------------------------------------- |
| `order_id`      | string   | `ORD-{epoch}` generated by workflow.               |
| `psid`          | string   | Link back to Users.                                |
| `customer_name` | string   |                                                    |
| `product`       | string   | e.g. `Panjabi`, `Saree`, `T-shirt`.                |
| `size`          | string   | `S` / `M` / `L` / `XL` / `Free`.                   |
| `quantity`      | number   |                                                    |
| `price`         | number   | BDT. Filled by human if AI does not know.          |
| `address`       | string   | Full delivery address.                             |
| `phone`         | string   | Bangla mobile.                                     |
| `status`        | string   | `pending` \| `confirmed` \| `shipped` \| `delivered` \| `cancelled` |
| `note`          | string   | Free text.                                         |
| `created_at`    | ISO date |                                                    |

---

## Tab 3: `Leads` (optional, used by follow-up workflow)

The follow-up workflow reads `Users` directly, but you can mirror leads here
for reporting. Skip this tab if you don't need it.

| Column            | Type     | Notes                                          |
| ----------------- | -------- | ---------------------------------------------- |
| `psid`            | string   |                                                |
| `name`            | string   |                                                |
| `last_message_at` | ISO date |                                                |
| `followup_sent_at`| ISO date | Last time we sent a nudge.                     |
| `outcome`         | string   | `pending` \| `converted` \| `dropped`          |

---

## Tab 4: `Products`

Your live product catalog. The AI reads this tab on every inbound message to
answer price, availability, size/color questions, suggest products, and confirm
orders with real prices.

| Column        | Type    | Notes                                                        |
| ------------- | ------- | ------------------------------------------------------------ |
| `product_id`  | string  | Unique ID, e.g. `PRD-001`.                                   |
| `name`        | string  | Display name, e.g. `Premium Panjabi - Navy Blue`.            |
| `category`    | string  | `Panjabi` \| `Saree` \| `Kurti` \| `T-shirt` \| …           |
| `size`        | string  | Comma-separated available sizes: `M, L, XL`.                |
| `color`       | string  | Comma-separated colors: `Navy, White, Black`.                |
| `price`       | number  | BDT. The AI quotes this to the customer.                     |
| `stock`       | number  | Current units available. 0 = out of stock.                   |
| `description` | string  | Short feature text (≤ 120 chars) for AI to summarize.        |
| `image_url`   | string  | Public image URL (for future rich replies).                  |
| `status`      | string  | `active` \| `inactive`. Inactive items are hidden from AI.   |

> **Keep it lean:** ideally < 50 active rows. The full tab is injected into the
> AI prompt as a compact table, so fewer rows = faster + cheaper tokens.

---

## Why this shape

- **`ai_enabled` is the kill-switch.** Every inbound message reads this flag first;
  if `FALSE`, the workflow exits before calling the LLM. This is how a human
  takes over a conversation.
- **`memory` lives in the same row** so we don't need a separate DB. Cheap and
  good enough for short clothing-brand chats.
- **`last_message_at`** powers the scheduled follow-up: "users who didn't reply
  in 24h and aren't closed".
